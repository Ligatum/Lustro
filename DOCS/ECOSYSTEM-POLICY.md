# 1. Project Mission

We created this policy to foster a healthy, open ecosystem that lasts. We want everyone - developers, researchers, and integrators to build on top of Lustro with confidence and creative freedom. Community created wrappers and tools are welcome and encouraged.

# 2. Our Guiding Principles

Lustro ecosystem is built on four core principles that guide our development and community interactions:

- Reference before fragmentation.

- Compatibility before optimisation.

- Transparency before claims.

- Collaboration before competition.

# 3. Reference Implementation

Ligatum maintains the canonical reference implementation of Lustro Core and is responsible for preserving its architectural integrity. Our main goal is to maintain a stable and secure reference standard that is meant to serve as a foundation for the whole ecosystem. That is why Lustro Core (as explicitly marked inside the source code) is considered SSoT (Single Source of Truth).

Community integrations, language bindings and surrounding tooling are encouraged, while Lustro Core remains the canonical reference for the architecture itself.

# 4. Language Bindings and Platform Integrations

We actively encourage the community to develop platform integrations, plugins and tooling around Lustro. To make this as seamless as possible, our reference implementation includes native support for Rust, C/C++ FFI and Python extensions. This API is to evolve and improve to match your needs. Community feedback is highly appreciated.

- **Developer Ownership:** When you create a language binding, driver, plugin or any other wrapper - your code belongs entirely to you.

- **Core Alignment:** Please note that regardless of the license chosen for your project, Lustro Core incorporated from the Licensed Work remains governed by the Ligatum Technology License (LTL).

# 5. Native Ports

Any public distribution of such ports of the Licensed Work as standalone libraries or packages remains governed by Ligatum Technology License (LTL).

# 6. Compatibility Promise

Ligatum is committed to maintaining long-term API stability. Breaking API changes will be introduced only when strictly justified by correctness, security, or long-term maintainability. Whenever breaking changes are necessary, comprehensive migration paths and detailed compatibility notes will be provided to the community well in advance.

# 7. Independent Research and Cryptanalysis

Lustro was built with an open-card philosophy, rooted in observation and experimentation. Scientific criticism and reproducible research strengthen the ecosystem and are encouraged. We strongly welcome:

- Independent statistical analysis and benchmarking.

- Rigorous third-party cryptanalysis.

- Academic research and formal verification.

- Publicly reproducible testing and alternative architectural evaluations.

# 8. Trademark Policy

We want community members to proudly showcase their work while keeping the identity of the project clear for everyone:

- Community-developed language bindings, wrappers, plugins, integrations and tooling are encouraged. Projects using the Lustro name should accurately describe their relationship and should not imply official status. Descriptive names such as *lustro-go*, *lustro-nodejs* or similar are some of the examples.

- Only software packages and repositories directly maintained by Ligatum may describe or market themselves as Official Lustro implementations or tools.

Use of the Lustro name in a manner that implies official endorsement or affiliation with Ligatum is not permitted without prior contact and mutual agreement.

# 9. Next Steps for Contributors

- To contribute improvements to the reference repository, please contact us directly. Our aim is to actively interact with the community.

Long-term success of Lustro depends not only on its implementation. It also depends on independent verification and open discussion. Your feedback is appreciated.

# 10. Security Research

We actively welcome security research and analysis as part of our open-card philosophy. If you discover something significant, we’d love to hear from you.
